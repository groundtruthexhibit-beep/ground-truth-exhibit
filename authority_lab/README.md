# Public Authority Lab v1

Authority Lab v1 is a deterministic, local-only public falsification harness for the published Ground Truth authority model. It is not the private Ground Truth core, a production authorization service, a policy engine, a certification system, or evidence that Ground Truth is secure or complete.

Run one fixture:

```text
python -m authority_lab run cases/authority_lab/LAB-V0-003.json
```

Run the bounded v1 set:

```text
python -m authority_lab run-all cases/authority_lab
```

The oracle uses only explicit fixture state and public contract semantics. Schema `authority-lab-v1` requires an exact current authoritative `objective_binding` before an encoded decision contract may contribute to authority at T1 or T3. The oracle derives admission from strict objective, contract, binding, independently admitted root/source, scope, lifecycle, generation, and authoritative-ordering relations. A candidate, requester, model, verifier, signature, provenance record, quorum, or consensus cannot establish its own source authority. The fixture's admitted root remains an explicit trust/input boundary; this lab does not prove ultimate root truth.

At T1 the binding is provisionally admitted from explicit binding facts. T2 remains non-authoritative and records ordered mutations. At T3 the oracle re-establishes current admission; cached T1 admission does not survive a relevant change. Missing, unknown, conflicting, wrong-scope, or unordered admission state yields `UNAVAILABLE`. Exact current authoritative rejection, invalidity, revocation, supersession, or prohibition yields `DENIED`. `AUTHORIZED` remains possible only after binding admission and every existing evidence, tuple, boundary, grant, consumption, delegation, closure, and commit-time requirement succeeds.

T2 mutation fields resolve through one immutable closed registry. Every exact canonical name and retained legacy alias maps to an evaluator-owned state, relation, objective-binding relation, or closed auxiliary fact. A structurally valid unregistered name is retained in the trace but returns `UNAVAILABLE` with `UNKNOWN_MUTATION_FIELD` before an authority conclusion. Case, whitespace, punctuation, namespaced, and non-ASCII variants are malformed input; the parser does not trim, case-fold, Unicode-normalize, strip namespaces, or infer aliases. No parsed mutation is display-only authority state.

The v1 contract and parser preserve exactly six tuple coordinates, six invariant identifiers, and three authority outcomes. Legacy `authority-lab-v0` inputs may be loaded for fail-closed diagnostics but can never return `AUTHORIZED`; unknown schema versions are rejected.

Authorization also requires positive observation admission and completeness; silence is not continuity. The `evidence_binding` relationship identifies an immutable observation profile, exact current objective binding and decision contract, current authority root, T1/T3 anchors, independently identified observers, fixed scope families, ordered coverage segments, exact observer handoffs, any admitted transformations, and root-issued lifecycle state. The `freshness` relationship binds that coverage to the current T3 anchor and root ordering source. Completeness is derived from those relations. The parser accepts neither an `observations_complete` boolean nor a `monitor_trusted` assertion.

Observer admission is root-only in Authority Lab v1. Objective-binding delegates, evaluated agents, observers, child agents, wrappers, summarizers, relays, transformed artifacts, and shared state cannot issue or inherit observation authority. A changed observer or stream requires an exact current root-issued handoff with continuous scope and interval coverage. Missing identity, admission, scope, ordering, freshness, coverage, handoff, or transformation continuity yields `UNAVAILABLE`; a current root-issued prohibition, rejection, invalidity, revocation, or supersession yields `DENIED`. Complete current root-issued coverage can still support `AUTHORIZED` after every other requirement succeeds.

Observation histories are admitted through strict `OBSERVATION_HISTORY_COMMITMENT` envelopes. The oracle recomputes a domain-separated SHA-256 digest over the exact envelope body and referenced segments, requires an independently admitted verifier result, an append-only predecessor link, and a root-ordered unique-head checkpoint. Verifier-bound freshness must select that exact checkpoint. A separate harness-owned state manifest supplies the durable checkpoint transition; fixture JSON cannot supply or select that anchor. Same-position forks, stale replay, generation rollback, missing consistency, unavailable verifier state, and conflicting witnesses return `UNAVAILABLE`. Explicit current revocation or prohibition remains `DENIED`. A current authentic append-only head can still support `AUTHORIZED`.

Commitment checkpoints additionally require a strict verifier-state anchor. Candidate-visible anchor/source records are joined exactly to `trusted_anchor_state.json`, a separate harness-owned current-anchor context that fixture JSON cannot supply. The join binds verifier and durable-store generations, the state key and stream generation, selected commitment head, monotonic anchor position and predecessor, boundary, root-issued source authority, and freshness. Locally consistent recovered manifests, counters, signatures, candidate replay, or matching labels do not establish that verifier memory is current.

Rollback, stale anchor replay, same-position head reuse, unresolved replica forks, circular candidate-data recovery, incomplete or reordered replay, unauthorized verifier/anchor replacement, and unavailable witness-source continuity yield `UNAVAILABLE`. Exact disaster recovery and authorized rotations remain reachable through an independently current recovery-eligible anchor, complete ordered replay, fresh verifier/store generation, installation receipt, post-installation anchor, and all ordinary authority requirements. Witness count does not establish independence: identity, source lineage, control domain, interval coverage, freshness, and lifecycle remain explicit relations.

Anchor currentness additionally requires a harness-owned, strictly typed adapter admission/currentness relation and a root-selected required-domain policy. Candidate fixtures cannot supply these relations. Adapter identity, generation, lineage, control/independence/rollback domain, scope, interval, lifecycle, ordering, freshness, and rotation must join exactly to the selected anchor. Witnesses join to protected source-domain membership; different names, keys, signatures, or domain strings do not establish independence. Every required domain must provide one current view. Missing domains, correlated sources, candidate-selected subsets, or unresolved cross-domain disagreement yield `UNAVAILABLE`; exact root-authorized reconciliation and adapter rotation preserve positive `AUTHORIZED` paths.

Control-plane independence closes the same protected model over every authority role actually consumed by the selected decision path: policy root, orderer, observer, commitment producer, verifier, anchor source, anchor adapter, witness source, and applicable reconciliation or recovery authority. A harness-owned all-applicable policy joins each exact role identity/generation to source lineage, controller, upstream dependency, rollback domain, scope, boundary, interval, lifecycle, ordering, freshness, and an admitted external independence-appraisal root. Required separation counts effective domains rather than roles, keys, signatures, processes, machines, or labels. Self-appraisal, circular or unclosed appraisal, favorable role subsets, stale membership, correlated recovery/reconciliation, and undeclared consolidation yield `UNAVAILABLE`; explicit current prohibition remains `DENIED`. Exact authorized consolidation counts as one authority, while exact appraised separation, rotation, recovery, genesis, and successor paths may still reach `AUTHORIZED`.

Delegated execution additionally requires a harness-owned, root-closed delegation authority context. The protected context binds an exact current policy, independently admitted principal identities and roles, immutable scoped grant edges, lifecycle and ordering records, any principal/grant successor transitions, and one terminal grant/use relation. Every edge must remain within its parent's actions, artifacts, tools, semantic scopes, boundaries, subject classes, validity interval, and depth; permission to act does not imply permission to delegate further. Cycles, partial chains, self-delegation, arbitrary delegators, candidate-selected roots, scope widening, stale or ambiguous heads, wrapper or relay inheritance, grant shopping, and predecessor reuse across a successor transition yield `UNAVAILABLE`. An exact current root-issued revocation or prohibition yields `DENIED`. Valid root-terminated multi-hop, service-account, planner/executor, genesis, and successor-specific chains can still reach `AUTHORIZED`. Candidate fixtures cannot supply the protected delegation context, and signatures, labels, shared state, generic evidence, or agreement cannot manufacture a delegation edge.

Human approval is optional unless a harness-owned current policy requires it. When required, the protected policy independently admits exact human/operator identities, roles, effective control domains, lifecycle and ordering heads, and durable use state. A strict `human_approval_binding` then joins the policy to the canonical request and effect digests, artifact, initiating subject, executor, delegation chain, tool/backend, credential generation, execution context, boundary epoch, session, issuance/expiry order, lifecycle, and use policy. Display text, `human_approval = "yes"`, ordinary action authority, candidate-selected approvers, signatures, or multiple names from one effective domain cannot establish approval authority.

Approval is revalidated at execution time. Changed artifacts, effects, recipients, parameters, subjects, executors, delegation chains, tools, credentials, boundaries, queued authority state, transformations, restarts, snapshots, recovery, or successors require the exact policy-permitted continuity or fresh approval. One-shot and bounded approvals join to protected use counters, so candidate input cannot reset consumption state. A current authoritative approval revocation or prohibition yields `DENIED`; missing identity, binding, currentness, independence, continuity, or replay state yields `UNAVAILABLE`. Approval never repairs an unrelated verifier, delegation, observation, or prohibition failure. Policy `NONE`, exact reusable approval, first one-shot use, independent multi-human approval, and fresh successor-specific reapproval remain capable of supporting `AUTHORIZED` after every other requirement succeeds.

T1 records the exact evaluated authority state, grant, effect, and consumption state, while T3 must establish exact evidence-to-artifact, boundary-to-epoch, execution-to-control-state, consumption-to-grant/effect, and any applicable delegation or closure relationships. `required_values` remains case input and cannot redefine oracle-owned relationships. A state, relational, or auxiliary-fact mutation requires a distinct, lineage-linked re-establishment even when an ordered mutation chain returns to its T1 value.

Re-establishing current state does not retarget an old grant. The immutable mutation registry assigns every accepted field both continuity effects and required observation-scope families. The oracle accumulates those effects over every ordered mutation edge, so an `A -> B -> A` path is not equivalent to an unchanged endpoint. Identity, terminal, or non-restorable lineage effects require an independently current successor chain: exact current identity and execution context, a fresh non-restored epoch and root/objective head, root-authorized observation coverage, and a distinct successor-bound grant/use relationship.

Predecessor grants are non-portable across identity, lineage, terminal, or incompatible grant/use discontinuities. Generic fresh evidence, old credentials, checkpoint equality, restored labels, or identical code do not admit a successor. `AUTHORITY_PRESERVING` grant transitions remain available only for non-terminal continuity-preserving changes; they cannot bridge a successor break or make a grant ABA path authoritative. Boundary `B1 -> B2 -> B1` is a repeated label, not restoration of the first lineage. Re-entry into the same named boundary remains possible under a fresh epoch and complete new authority chain. Observer handoff preserves observation coverage only and never transfers predecessor execution authority. Missing or ambiguous continuity yields `UNAVAILABLE`; an exact applicable current revocation or prohibition remains `DENIED`.

The oracle fixes the actual authority outcome before reading the expected outcome. `PASS` means only fixture/oracle agreement. It does not mean secure, safe, production-ready, certified, formally verified, or universally correct. `CASE_MISMATCH` is valuable: it can expose a fixture defect, oracle defect, ambiguous specification, or candidate contract counterexample. Neither term is an authority outcome.

Authority Lab v1 assumes fixture-provided root facts and harness-provided durable checkpoint and current-anchor state as admitted inputs. `KNOWN` means the value passes these executable relational checks; it does not prove that a real external monitor emitted the underlying events or that the admitted root, orderer, verifier, anchor adapter, or protected state store is ultimately truthful. If every anchor/comparison source and candidate history is rolled back or compromised consistently and no contrary evidence survives, the deterministic oracle cannot infer the missing world state. Real-world instrumentation completeness, event delivery, signature appraisal truth, key custody, hardware isolation, witness independence, adapter atomicity, and root correctness remain `TRUST_PRECONDITION`s outside this bounded lab. Authority Lab v1 does not establish production observation trust.

External engineers are encouraged to submit minimal reproducible break cases with exact facts, contract interpretation, allegedly bypassed invariants, and deterministic reproduction steps. Contributor expectations never control the oracle and create no authority.

This bounded implementation requires no network, implicit wall clock, external service, or model judgment and uses only the Python standard library. Its existence does not authorize deployment, production use, roadmap advancement, a later phase, or private-core modification.
